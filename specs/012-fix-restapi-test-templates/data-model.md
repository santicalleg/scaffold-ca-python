# Data Model: Fix RestAPI Entry Point Test Templates

**Feature**: `012-fix-restapi-test-templates` | **Date**: 2026-04-10

This feature involves no persistent storage or domain entities. The "data model" here
describes the template context objects that drive code generation.

---

## Template Context

All restapi Jinja2 templates receive the same `ctx_dict` assembled in `_generate_entry_point_impl`.

### `ProjectContext` fields used in templates

| Field | Type | Example | Usage |
|---|---|---|---|
| `project.name` | `str` | `"MyApp"` | Docstrings, class names |
| `project.python_package` | `str` | `"my_app"` | Import statements |

### `ModuleContext` fields used in templates

| Field | Type | Example | Usage |
|---|---|---|---|
| `name` | `str` | `"restapi"` | Module identifiers |
| `layer` | `Layer` | `Layer.ENTRY_POINTS` | Not used in restapi templates directly |
| `subtype` | `str` | `"restapi"` | Not used in test templates |

### Extra keys in `ctx_dict` (restapi-specific)

| Field | Type | Present when | Usage |
|---|---|---|---|
| `routes` | `list[tuple[str, str]]` | `--swagger` provided | Swagger route stubs in `schemas.py.jinja2`, `rest_controller.py.jinja2` |
| `enable_kafka` | `bool` | Always | `False` for restapi; used only by agent templates |
| `enable_mcp_client` | `bool` | Always | `False` for restapi; used only by agent templates |

## `ExampleResponse` Schema Model

```
ExampleResponse
  status: str = "ok"    ← Pydantic v2 BaseModel field with default
```

When swagger routes are provided, additional per-route response models are appended:
```
<Method><Path>Response (e.g., GetUsersResponse, PostOrdersResponse)
  # placeholder fields — user replaces with domain types
```

These models live in `schemas.py` and are imported by `test_schemas.py`.
